# 实现边界、运维与安全

## 不是整个领域的穷尽监控

首版只从 arXiv 的四组词法查询发现新文献。CVF/OpenReview/期刊正式上线、代码发布日期、撤稿状态、未上 arXiv 的论文不会自动全面覆盖。关键词有漏检和误检，不应将没有匹配结果解释为没有相关研究。

后续可增加独立来源适配器，每个来源保留自己的抓取游标、请求限制与失败状态。不要把多站网页爬取写进一个遇错就整批清空的脚本。

## 日期与版本

新发现通过 arXiv 文档支持的 submittedDate 日期范围查询。首发 published、来源更新 updated、本站首次发现 first_seen 分开。没有使用未经文档确认的 lastUpdatedDate 日期过滤字段。

旧库版本通过 id_list 查询；每轮 40 个编号，按排序列表轮转。缺失/撤下或请求失败的批次会报告失败，游标继续转到下一批，避免一个坏 ID 卡死所有旧文献；失败批次在下一次轮转重试。不能承诺每一篇旧论文每天都检查到。

每条新论文查询成功后保存 completed_until。失败不移动游标。重叠 7 天应对短期延迟，但不能保证覆盖无限期索引延迟。长时间中断每次最多追赶一个 30 天块，网页 backlog_days 会提示仍在回查。

按 arXiv/DOI 强标识关联；标题相同只提示，不自动合并。预印本与正式版缺少强标识关联时仍可能分别保留。禁止以模糊标题去重直接删除用户论文。

## 自动分类与人工层

自动规则仅根据词法线索；引用背景可能导致标签误命中。Open-set/Open-world 不是自动 OV 标签；使用 CLIP/VLM 也不是 OV 的充分条件；实例分割和语义分割分开。医学、体数据、检测与分类等边界仍可能需要人工排除。

人工层 editorial.json 独立于抓取记录。它可以改变展示分类、设为排除、精选或选择公开。自动脚本不写这个文件。full-text-read 必须来自人工设置，不由摘要长度推断。

人工核对状态还绑定 reviewed_version。来源版本变化时，网站显示“版本已变化·需重新核对”，不会把读过 v1 自动解释成读过 v2。使用 review.py 设置已核对状态会记录当前版本；直接编辑 JSON 时，也应填写已核对的整数版本号。

## 可选模型调用

启用后会把**所选论文的 PDF 页面文本节选**（默认最多 40 页、约 6 万字符）发送给模型提供方；不发送整个 Zotero 库、附件路径、私人笔记或密钥内容。模型提供方仍会收到这些文本；启用前应确认你的数据政策。PDF 仅从 arxiv.org 下载到本地缓存（.cache/pdfs，已 gitignore），不公开托管、不重新分发。

模型输出必须满足：每条中文结论附 1-2 条逐字引用与页码；引用必须能在对应页面文本中找到；结论中的数字必须出现在引用里；信息不全时要求写“未说明”。这些是机械校验，不能证明观点、比较对象与因果解释正确。草稿始终是“AI 生成 · 待人工复核”，不会自动变成精选或全文精读。

修订后旧草稿标记 stale、不再展示，等待重新生成。调用上限按成功写入仓库的状态计数（默认每轮 8 篇、每日 24 篇，可用工作流输入的 `drafts` 手动补跑）；不是提供方硬金额上限。运行中断、强制回滚或 git push 失败可能丢失最新预算记录，导致再次调用。不要将此限制当成绝对的费用保障。

## Zotero

可选读取仅针对一个明确的集合，不递归子集合。每次分页读取，再添加尚未存在的公开题录字段；不做双向同步、不自动反映删除、不覆盖旧题录、不写标签回去。

记录的 Zotero 原始 item key 和 library ID 不放入题录，内部 zref ID 是稳定摘要；无需重新将 library.json 导入 Zotero。网页导出的 RIS 仅是选择性保存入口，重复导入同一批仍可能产生重复。

## 公开策略

站点构建只允许明确字段，不复制私有记录，不把对象整个序列化到网页。输出目录中出现未知文件时会拒绝构建，避免把残留附件/私密文件一并部署。

但公开 GitHub 仓库会公开其中所有已提交文件。data/store.json 保存公开来源摘要和可选 AI 草稿；网页不显示并不意味着仓库不可读。需要仓库级保密时，请采用恰当的私有仓库/发布方案，不要仅靠前端筛选隐藏。

不要将原始 PDF 公开托管或把第三方内容视为代码许可的一部分。当前默认网页只展示题录链接；摘要全文和 AI 草稿显示需显式开启并检查适用权利。

## 长期运行

每天工作流成功不保证当天一定有新论文。网站在最近完整成功时间超过 48 小时后显示记录过期提示。RSS 和事件用于观察变化；外部失败没有伪装成“无新论文”。

GitHub 任务可能延迟/停用；API 会限流或改变行为；查询会随领域术语变化而需要更新。生成候选和事件不断增长，应定期备份与评估存储。近期运行保留 90 次、事件保留 5000 条；论文不会按时间自动删除。

没有部署账号实测的模块不要直接视为生产已验收。首次验收必须检查真实查询、状态提交和 Pages 发布，后续再确认一次计划触发。
